# Importare le schede 1000bit

L'operatore ha dichiarato di avere il permesso per il recupero dei dati.
L'adattatore usa il formato reale della scheda **Amiga 1200**, ID **282**,
fornita come HTML in questa conversazione. Non esegue JavaScript, invia moduli,
segue collegamenti pubblicitari o scarica fotografie, manuali e ROM.

## Prova su Windows

Sul branch `feat/historical-data-import`:

```powershell
git pull --ff-only
docker compose up --build -d
```

Mantieni l'eventuale nome progetto `-p` della tua istanza. Premi Ctrl+F5 e apri
**Amministrazione → Importazioni → Fonte dati → 1000bit**.

1. Mantieni **Aggiorna solo calcolatori già presenti** per arricchire l'archivio
   senza aggiungere modelli. Questa è l'impostazione predefinita per 1000bit.
2. Carica il file `.html`/`.htm` salvato dal browser, oppure il JSON prodotto
   dal raccoglitore. Resta supportato anche il normale formato canonico CSV/JSON.
3. Conferma i diritti nel modulo di caricamento e prepara l'anteprima.
4. Controlla la scheda associata. Se manca o ci sono corrispondenze ambigue,
   cerca il modello esistente e associalo prima di applicare. Con l'opzione
   attiva, le righe non associate vengono escluse senza creare calcolatori.
5. Premi **Applica le righe pronte all'archivio** e controlla esito e
   **Fonti e verifiche** nel risultato corrente. Le informazioni restano da
   verificare; differenze rispetto ai valori attuali non li sovrascrivono.
6. Ripeti il caricamento: a parità di dati, l'esito deve essere **Invariata**.

Per inserire un modello assente puoi disattivare esplicitamente l'opzione
**Aggiorna solo calcolatori già presenti**, controllando l'anteprima.
Categorie, descrizioni già scritte, fotografie e altri dati preesistenti non
vengono eliminati. Il riconoscimento include l'alias attestato dalla scheda
`Commodore Business Machines (USA)` per il produttore Commodore.

La scheda salvata contiene il suo URL originale. Per file che ne sono privi
puoi compilare **URL originale della scheda HTML**. Un URL discordante con
quello incorporato viene rifiutato. Gli indirizzi citano esclusivamente
`https://www.1000bit.it/scheda.asp?id=…`.

## Recupero diretto dal computer dell'operatore

Nel medesimo pannello inserisci da **uno a cinque URL di schede**, uno per
riga, quindi premi **Recupera dalla fonte e prepara anteprima**.
Non ci sono salvataggi automatici nel catalogo: segue la normale anteprima.

Le richieste sono seriali, con almeno cinque secondi di pausa. Il raccoglitore
legge `robots.txt` e rispetta divieti, Crawl-delay e Request-rate. Non visita
l'intero database, non enumera ID e non segue automaticamente le altre schede.
Un errore di rete totale produce un lavoro fallito e ripetibile; un recupero
parziale conserva pagine riuscite ed esiti mancanti come righe non importabili.

Il proxy cloud continua a rifiutare il sito con **403**: questo non è un
rifiuto di 1000bit e non indica che il recupero dal computer dell'operatore
fallirà. Il caricamento HTML funziona anche senza accesso di rete a 1000bit.
Il recupero remoto con risposte valide è testato con HTTP sintetico, non con
pagine scaricate dal cloud.

Per conservare prima le pagine in un file locale, il raccoglitore CLI resta
utilizzabile. Sostituisci `URL_REALE_DELLA_SCHEDA` con l'indirizzo effettivo:

```powershell
docker compose exec api python -m app.importing.collect_1000bit --url "URL_REALE_DELLA_SCHEDA" --output /tmp/1000bit-schede-01.json
docker compose cp api:/tmp/1000bit-schede-01.json ./1000bit-schede-01.json
```

**Il JSON `hhe-1000bit-pages-v1` ora è caricabile scegliendo la fonte 1000bit.**
Puoi ripetere `--url` fino a cinque pagine e aumentare `--interval` per le
condizioni concordate. I file di output esistenti non vengono sovrascritti.
I limiti sono 1 MiB per pagina raccolta, 128 KiB per robots e 8 MiB per import.

## Informazioni estratte e limiti semantici

La tabella `tabDatiTecnici` fornisce nome, costruttore, CPU, RAM, ROM, formato,
sistema operativo, modalità testo, grafica, audio, storage e porte, se presenti.
Gli altri campi tecnici non vuoti diventano note con fonte. Il campo `User`
non diventa una caratteristica del computer. Le righe non riconosciute come
schede valide vengono segnalate, senza inventare dati da login, menu o annunci.

- **CPU**: modello e frequenza vengono separati solo se il formato è univoco.
  Nel campione: `68EC020` e `14.4 MHz`, senza attribuire un produttore non indicato.
- **RAM e ROM**: `2Mb - 16Mb` e `512Kb` restano come scritti nella fonte.
  Non si assume che `b` significhi byte; l'intervallo RAM non genera opzioni
  ordinabili o combinazioni inventate.
- **Espansioni opzionali**: le CPU di terze parti citate nelle note restano
  nelle note, senza diventare processori della dotazione di base.
- **Produzione**: inizio/fine produzione restano fatti contestuali, con la
  precisione originale. Non diventano automaticamente date commerciali.
- **Tipo**: `Desktop` è un formato, non una categoria storica dedotta.
- **Prezzi**: si importa un solo importo positivo non ambiguo con valuta
  esplicita riconosciuta, senza inventare data o mercato. Importi multipli,
  separatori ambigui e simboli generici come `$` o `£` restano note. Lo zero
  senza valuta e i campi vuoti non diventano prezzi gratuiti.
- **Descrizione italiana**: breve sintesi dei dati registrati; non sostituisce
  una descrizione preesistente e non aggiunge giudizi storici non documentati.

Il formato è verificato sulla pagina italiana fornita. Altri layout, lingue,
pagine di catalogo, esportazioni non documentate o schede che usano un altro
formato richiedono verifica: non si dichiara copertura dell'intero archivio.

## Originali, fonti e CLI di importazione

Ogni dato tecnico porta una citazione alla scheda, un estratto del campo e lo
SHA-256 dell'HTML. Il file originale completo resta nel lavoro e può essere
scaricato. Per HTML legacy Windows-1252/Latin-1 viene conservato internamente
in Base64 e restituito senza cambiare i byte; le pagine del raccoglitore sono
conservate nel loro involucro JSON con SHA-256 verificato prima dell'adattamento.
Due copie diverse dello stesso ID nella stessa raccolta sono rifiutate anziché
scegliere silenziosamente una versione. Le copie identiche sono deduplicate.
Nessuna licenza aperta o verifica storica viene presunta.

```bash
python -m app.importing /percorso/scheda.html --provider 1000bit --rights-confirmed
python -m app.importing /percorso/scheda.html --provider 1000bit --rights-confirmed --apply
```

La CLI usa gli stessi adattatori di upload e retry. `--source-url` specifica
l'origine se manca nel file; `--no-existing-only` abilita esplicitamente nuovi
modelli. Un file non viene applicato senza `--apply`.

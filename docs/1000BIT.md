# 1000bit: raccolta autorizzata delle schede

L'operatore ha dichiarato di avere il permesso per il recupero dei dati di
1000bit. Questo non viene registrato come una licenza aperta né come verifica
storica delle informazioni. Non vengono scaricate fotografie, ROM o manuali.

## Stato dell'integrazione

È disponibile un raccoglitore di pagine originali, eseguibile sul computer
dell'operatore. Non è ancora un importatore delle schede: il proxy cloud
rifiuta homepage e `robots.txt` con **403**, prima di raggiungere il sito.
Non è stato quindi possibile verificare il vero HTML delle tabelle, la
struttura del catalogo o eventuali esportazioni/API offerte dai gestori.

Il formato delle schede non viene ipotizzato. Prima di abilitare un adattatore
automatico nell'interfaccia serve almeno una pagina reale da esaminare,
oppure l'esportazione autorizzata fornita dai gestori. Il caricamento canonico
CSV/JSON con fonte **1000bit** resta disponibile nel pannello Importazioni.

## Raccogliere una scheda sul proprio computer

Dal branch `feat/historical-data-import`, aggiorna e ricostruisci il backend:

```powershell
git pull --ff-only
docker compose up --build -d
```

Apri una scheda nel browser e copia il suo indirizzo HTTPS effettivo. Sostituisci
`URL_REALE_DELLA_SCHEDA` nel comando seguente: non è un percorso predefinito.

```powershell
docker compose exec api python -m app.importing.collect_1000bit --url "URL_REALE_DELLA_SCHEDA" --output /tmp/1000bit-scheda-01.json
docker compose cp api:/tmp/1000bit-scheda-01.json ./1000bit-scheda-01.json
```

Puoi ripetere `--url` per un massimo di cinque pagine esplicitamente scelte.
Le richieste sono seriali, con almeno cinque secondi di pausa; usa
`--interval 10` o un intervallo maggiore per rispettare eventuali condizioni
concordate. Il raccoglitore legge `robots.txt`, applica divieti, `Crawl-delay`
e `Request-rate`. Non scandisce collegamenti o intervalli di identificativi.

In caso di blocco di rete, HTTP 429 o altri errori, la raccolta si interrompe
conservando pagine riuscite, errore e URL ancora in attesa. Non esegue
ritentativi automatici. Per riprendere, usa gli URL da ritentare e un nuovo
nome di output; i file già presenti non vengono sovrascritti. Se `robots.txt`
restituisce un divieto o una risposta non interpretabile, il file riporta il
motivo e nessuna scheda vietata viene scaricata.

## Contenuto del file

Il JSON `hhe-1000bit-pages-v1` conserva URL richiesto e finale, data di accesso,
Content-Type, contenuto originale in Base64 e SHA-256 di ogni pagina. Conserva
anche il `robots.txt` consultato e gli esiti della raccolta. I limiti sono
1 MiB per pagina, 128 KiB per robots e 8 MiB per il file completo. I redirect
sono limitati a HTTPS sugli host `1000bit.it` e `www.1000bit.it`.

**Questo file non va caricato nel normale importatore CSV/JSON.** Serve per
analizzare la struttura reale e costruire l'adattatore, conservando gli
originali. Il comando non accede al database e non crea né modifica calcolatori,
fonti o verifiche. In alternativa, una pagina può essere salvata direttamente
dal browser per l'analisi offline.

## Verifiche e dati effettivi

Test HTTP sintetici per originali e impronte, attribuzione, limiti di risposta,
URL e redirect, rispetto di robots, pause, richieste rifiutate ed errori proxy
senza esposizione di credenziali. Nessun dato di questi test è storico.

I 27 test del raccoglitore sono passati. Suite backend completa: 227 passati
su SQLite e uno specifico PostgreSQL saltato; 228 passati su PostgreSQL isolato.
Verificati anche la build Docker dell'API e
l'esecuzione del comando `--help` nell'immagine. Nessuna nuova dipendenza
Python necessaria. Il frontend non viene modificato da questa preparazione.

Il tentativo reale dal cloud è stato rifiutato dal proxy. **Zero schede reali
recuperate e zero dati storici importati da 1000bit** in questa fase.
